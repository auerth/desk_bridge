# ADR 0006 - Windows service, secure-desktop helper and watchdog (M6)

* Status: **Proposed** (implemented; needs the manual laptop acceptance test below)
* Date: 2026-10-16
* Deciders: Thorben (owner), implementation by the M6 service work
* Related: plan 6.1, 8.1 (UIPI, Ctrl+Alt+End), 11, 13 (watchdog), 15/M6, 16; `crates/service`, `crates/agent/src/secure.rs`

## Context

M6 acceptance: the UAC prompt and the lock screen of the laptop must be usable with the PC keyboard
and mouse, a crashing agent must never leave keys stuck, and the agent must restart by itself.

Windows constraints that shape the design:

* UAC consent, lock screen, logon screen and the Ctrl+Alt+Del screen live on the **secure desktop**
  (`winsta0\Winlogon`). A normal user process, even elevated, cannot open it or inject input there;
  only a SYSTEM process attached to that desktop can.
* A service lives in **session 0**, which has no desktop the user sees. Anything interactive has to be
  started into the user's session with a token for that session.
* UIPI: a non-elevated process cannot send input to elevated windows, so the agent already runs
  elevated (scheduled task, ADR-less decision in plan 6.1).
* `SendSAS` (Ctrl+Alt+Del) can only be generated by a service (or an ease-of-access app) and only if
  the `SoftwareSASGeneration` policy allows it.

## Decision

1. **One service, `DeskBridgeService`** (LocalSystem, auto start, registered by `deskbridge-setup`),
   in the same binary as the helper (`deskbridge-service.exe --helper`). SCM glue is hand-written on
   the `windows` crate (no `windows-service` dependency: not in the offline registry, and ~150 lines).
2. **Agent supervisor.** The scheduled task *DeskBridge Agent* stays the normal way to start the
   agent. The service only fills gaps: it polls once per second and starts the agent when none is
   running, using `WTSQueryUserToken` -> `TokenLinkedToken` (elevated half of a split token) ->
   `DuplicateTokenEx(TokenPrimary)` -> `CreateProcessAsUserW` on `winsta0\default` with a
   `CreateEnvironmentBlock` environment. "Running" = the single-instance mutex exists or a
   `deskbridge-agent.exe` runs in the console session, so a second instance is never started.
   Grace 20 s after a logon (for the task), then backoff 1, 1, 2 ... 30 s, reset after 60 s healthy.
   Exit code 0 means "user quit it" and is not restarted until the next logon. Stopping the service
   does **not** stop the agent.
3. **Watchdog.** The service logs the agent's exit code (it holds a process handle, also for agents
   it only adopted). The key release itself happens in the **restarted agent**
   (`release_stuck_keys()`: key-up for everything `GetAsyncKeyState` reports down, injected with our
   marker; only on devices that are not an input source), and in the **helper**, which releases
   everything when its pipe client disconnects. We rejected "service injects the key-ups itself":
   it would need the service to know the key state of another session.
4. **Helper.** SYSTEM token duplicated from the service, `TokenSessionId` set to the console session
   (`SetTokenInformation`), `CreateProcessAsUserW` with `lpDesktop = winsta0\winlogon`. It exits when
   the service dies (`--parent-pid`), is restarted on session/user change and after crashes (same
   backoff). Injection reuses `WinInputInjector` (same keymap, same marker) on a dedicated thread that
   re-attaches to the input desktop whenever its name changes.
5. **Routing in the agent.** `SecureDesktopInjector` probes `OpenInputDesktop` (cached 100 ms): name
   `Default` is normal; any other name or `ERROR_ACCESS_DENIED` is secure. On a switch it releases on the
   side it leaves. If the helper is unreachable it falls back to normal injection and logs once.
6. **Pipes.** `\\.\pipe\deskbridge-helper` and `\\.\pipe\deskbridge-service`: DACL `SYSTEM` + user SID
   of the console user (regenerated on logon/logoff), `reject_remote_clients`, `first_pipe_instance`
   (no squatting), and the label `S:(ML;;NW;;;HI)`. The label is the important part: without it any
   medium-integrity process of the same user could drive the SYSTEM helper and type into the UAC
   prompt, i.e. bypass UIPI and UAC. The client opens with `SECURITY_IDENTIFICATION` so a rogue server
   cannot impersonate the agent. Binary, length-prefixed protocol, injection commands without answer.
7. **`SendSAS`** is loaded dynamically from `sas.dll` (System32 only) and called with `AsUser = FALSE`.
   The service never changes system policy; it checks `SoftwareSASGeneration` (1 or 3) first and answers
   with a clear error otherwise (Windows would silently ignore the call). The installer (or the owner
   once) sets the policy: `reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v SoftwareSASGeneration /t REG_DWORD /d 1 /f`.
8. **Console mode** `deskbridge-service.exe --console [--no-sas] [--no-agent] [--no-helper]` for tests
   without installing the service.

## Consequences and risks

| Risk | Impact | Mitigation / status |
|---|---|---|
| **Session 0 isolation**: the service itself has no desktop | none, by design | everything interactive runs as a child in the console session |
| **Token juggling** (`TokenLinkedToken`, SYSTEM token with changed session id) needs `SeTcbPrivilege` / `SeAssignPrimaryTokenPrivilege` | works only as LocalSystem; `--console` as a normal admin cannot start agent/helper | documented; use `psexec -s` for console tests |
| **Lock screen / logon screen limits** | the logon screen after a reboot cannot be driven: the agent (a user process) does not exist yet. Lock screen and UAC work because the agent keeps running | accepted for v1; a SYSTEM-level agent would be a later ADR. Fast user switching: the helper follows the console session, the other session's agent is not supervised |
| **UIPI bypass via helper** | a local privilege-escalation surface | DACL + High-integrity label; only elevated processes of the console user reach the helper. The helper accepts only input commands (no file/process APIs) |
| **Windows Hello / PIN / password fields** | key injection works, but credential providers may reject synthetic input in rare cases; Ctrl+Alt+Del screen itself requires the SAS policy | to be verified on the laptop |
| **Screen-saver desktop and `Secure` classification** | treated as secure; helper (SYSTEM) can still inject | acceptable |
| **AV false positives** | a service that launches SYSTEM processes into user sessions and injects input looks like malware to heuristics | sign the binaries when a certificate exists, keep one binary with fixed names, document in README/SECURITY, submit to vendors before release |
| **Stuck keys after a crash during a desktop switch** | key-up lands on a desktop that no longer has focus | switch triggers `release_all` on both sides; helper releases on disconnect; agent releases at startup |
| **Restart storms** | CPU/log noise | capped backoff, one log line per event |
| **Agent exit code 0 treated as "quit"** | an agent that exits 0 because another instance already runs is correctly ignored; a crash that exits 0 would not be restarted | agent exits non-zero on engine failure |

## Manual acceptance test (owner, laptop)

See the report of the M6 work item; in short: UAC prompt and Win+L lock screen driven from the PC,
Ctrl+Alt+End, kill the agent while a key is held and check it is released and the agent is back within
a few seconds.
