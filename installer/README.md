# installer/

Everything the Windows installer needs beyond what Tauri generates (plan sections 12.1 / 12.2).

| Path | Purpose |
|---|---|
| `hooks.nsh` | Tauri 2 NSIS hooks (`NSIS_HOOK_PREINSTALL`, `..._POSTINSTALL`, `..._PREUNINSTALL`, `..._POSTUNINSTALL`) |
| `stage/` | **Generated** by `scripts/stage-installer.ps1` (git-ignored): the payload that is bundled |

## Flow

```
DeskBridge-Setup-x.y.z.exe  (NSIS, per-machine, admin)
  PREINSTALL    stop service / scheduled task / agent so files can be replaced
  (Tauri)       copy Desk Bridge.exe + bundle.resources, shortcuts, uninstaller, WebView2
  POSTINSTALL   deskbridge-setup.exe install --quiet --install-dir "$INSTDIR"
                  -> firewall rule (UDP 47820 + 5353, Private), scheduled task "DeskBridge Agent",
                     SendTo shortcut, drivers from drivers\drivers.json, installed.json
                launch the UI de-elevated (silent/passive installs only; the GUI finish page has
                its own "Run" checkbox)
uninstall
  PREUNINSTALL  stop processes, ask "delete user data too?" (default No; /S keeps it),
                deskbridge-setup.exe uninstall [--purge-user-data]
  (Tauri)       delete bundled files, shortcuts, registry
  POSTUNINSTALL delete installed.json and empty directories
```

* **Upgrade / update:** user data is never touched. The Tauri updater runs the installer with
  `/UPDATE`; the hooks then skip the uninstall branch. `deskbridge-setup install` is idempotent, so
  the firewall rule, task and shortcut are simply re-registered. Drivers are only updated when the
  INF version is newer (`UpdateDriverForPlugAndPlayDevices` without `INSTALLFLAG_FORCE`).
* **No reboot** is needed; if a driver update reports "reboot required" it is logged to
  `%LOCALAPPDATA%\softwelop\DeskBridge\logs\setup.log`.
* The hooks file uses `nsis_tauri_utils::RunAsUser` (shipped with Tauri) so the UI never runs
  elevated. Only the agent is elevated (via the scheduled task).

## Needed additions to `app/src-tauri/tauri.conf.json`

`hooks.nsh` is already referenced (`bundle.windows.nsis.installerHooks`: `"../../installer/hooks.nsh"`).
What is **still missing** is shipping the other binaries. The UI agent owns the file, so these are
the snippets to merge into `bundle`:

```jsonc
"bundle": {
  // Paths are relative to app/src-tauri/ . Map form: "<source glob>": "<destination below $INSTDIR>".
  "resources": {
    "../../installer/stage/deskbridge-agent.exe":   "deskbridge-agent.exe",
    "../../installer/stage/deskbridge-service.exe": "deskbridge-service.exe",
    "../../installer/stage/deskbridge-setup.exe":   "deskbridge-setup.exe",
    "../../installer/stage/ffmpeg/*.dll":           "./",
    "../../installer/stage/drivers/**/*":           "drivers/"
  },
  "windows": {
    "webviewInstallMode": { "type": "offlineInstaller" },   // already set
    "nsis": { "installMode": "perMachine", "installerHooks": "../../installer/hooks.nsh" }
  }
}
```

Notes:

* Put the payload **next to `Desk Bridge.exe`** (destination `deskbridge-*.exe`, DLLs into `./`).
  The firewall rule and the task point at `$INSTDIR\deskbridge-agent.exe`, and the agent finds the
  FFmpeg DLLs through the normal DLL search order (application directory).
* The hooks tolerate the alternative layout `$INSTDIR\resources\...` (they look for
  `deskbridge-setup.exe` there if it is not in `$INSTDIR`), but the two layouts must not be mixed.
* Why `resources` and not `externalBin`: `externalBin` requires target-triple suffixed file names
  (`name-x86_64-pc-windows-msvc.exe`) and is meant for sidecars that the app spawns by name. The
  agent/service/setup are spawned by the task scheduler / SCM / hooks by path, so plain resources
  are simpler. If the map form with a glob does not preserve sub-directories in your Tauri
  version, list the driver files explicitly (`stage/drivers/display/MttVDD.inf` ... ) - verify with
  the first `npm run tauri build` and look at `Section Install` in
  `target/release/nsis/x64/installer.nsi`.
* Tauri deletes only the files it knows about on uninstall. The hooks remove `installed.json` and
  the now-empty directories afterwards.
* `drivers/**` also contains `drivers.json`, the catalogue read by `deskbridge-setup install`
  (generated by `stage-installer.ps1`, format below).

## Driver catalogue (`drivers/drivers.json`)

```json
[
  {
    "name": "Desk Bridge Display",
    "inf": "drivers/display/package/MttVDD.inf",
    "hwid": "Root\\MttVDD",
    "enabled": true,
    "files": [
      { "from": "drivers/display/config/vdd_settings.deskbridge.xml",
        "to":   "C:\\VirtualDisplayDriver\\vdd_settings.xml" }
    ]
  }
]
```

`inf` and `files[].from` are relative to the install dir and must not contain `..`;
`files[].to` is an absolute destination. Files are copied before the device is created and removed on
uninstall. The hardware ID must be declared in the INF (`deskbridge-setup driver inspect --inf <file>`
lists them). A driver is only installed when the catalogue is present, so M0-M4 installers (no
drivers) simply skip the step.

Not implemented yet (needed for the display driver, see `drivers/display/README.md`): importing the
driver publisher certificate into `LocalMachine\TrustedPublisher` before the silent install. It lands
with M5b once ADR 0004 is accepted.

## Building the installer locally

```powershell
pwsh scripts/stage-installer.ps1            # builds release binaries + stages payload (add -NoFfmpeg to skip FFmpeg)
cd app; npm ci; npm run tauri build         # produces app/src-tauri/target or ../../target/release/bundle/nsis/*.exe
```

Tauri downloads NSIS and the NSIS plugins itself on first use; nothing has to be installed.

## Silent options (for testing)

| Switch | Meaning |
|---|---|
| `/S` | silent install/uninstall (uninstall keeps user data) |
| `/P` | passive (progress only) |
| `/UPDATE` | update mode (used by the Tauri updater): no uninstall of the old version |
| `/D=C:\path` | install directory (must be last) |
